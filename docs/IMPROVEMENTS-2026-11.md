# 300 improvements (November 2026)

Found by research (CRM, delivery/PSA, incentive-comp tools), workflow QA as sales / delivery / finance-HR-PRC users, a live site pass and 32 real-browser user journeys in CI; built by ten workstreams of 30. Sources reference the discovery findings (e.g. qa-finance#8).

## W1 · Platform & security

1. Server-side pay-data redaction on GET — /api/workspace (and every 409 body) returns employeeProfiles pay/status fields, bonusRuns.lines, deferredBonuses, probationOutcomes, clawbacks (+ any comp/me/engine pay collection) in full only to viewers whose HR record holds a pay role; everyone else gets their OWN lines only, others' profiles redacted (salary 0, disciplinary detail collapsed into goodStanding=false, `redacted: true`) — src/lib/sync/server-policy.ts, src/app/api/workspace/route.ts (source: must a, qa-finance#2, research-comp#1, live-pass#1)
2. Server merge on PUT from non-privileged writers — restricted collections are taken from the stored copy (never overwritten/erased); own HR row may change only self-service fields (e.g. Annex B signature) — server-policy.ts, workspace route (source: must a, research-comp#1)
3. Privilege-escalation guard — non-privileged writers cannot change governanceRoles, users[].email, delete users/HR rows or add a user with someone else's email (identity hijack via the synced users collection) — server-policy.ts (source: own, qa-finance#4 follow-on)
4. Append-only auditLog collection — server unions auditLog by id on every PUT (stored entries can never be edited or removed, by anyone, incl. restore/"Keep mine"/overwrite) — server-policy.ts (source: qa-finance#34, research-comp#29)
5. No impersonation for SSO users — canActAs only in demo/dev (never with a verified Access identity); unmatched Access user becomes a no-privilege guest with "No workspace user — ask HR to add you" instead of silently being the CEO — src/lib/sync/identity.ts, sidebar-extras.tsx, settings (source: must b, qa-finance#4)
6. /api/me resolves the workspace user server-side — returns mode, matched userId, governance roles, data scope (full/own) and admin flag from the stored snapshot; WORKSPACE_ADMINS break-glass list — src/app/api/me/route.ts, src/lib/sync/server.ts (source: must b)
7. Locked-workspace client handling — 401/403 lock codes put sync into a "locked" state: no polling/pushing (retry every 10 min or on demand), local work continues, edits stay queued — src/lib/sync/engine.ts (source: must c, live-pass#1)
8. Locked / unmatched banner — dismissible banner in the shell ("Shared workspace locked — working on this device only", Retry, Details → Settings) — src/components/shell/sync.tsx (source: must c)
9. Settings › Identity explains the security state — Access configured?, mode, verified email, matched user, server roles/scope, workers.dev/preview risk, locked reason and fix — settings/workspace-sections.tsx, /api/health (source: must c, live-pass#1)
10. Settings › Data admin-only — backup/restore/reset only for useAccess().admin; others see why — settings/data-sections.tsx (source: must d, qa-finance#3)
11. Restore hardening — non-admin restore impossible in UI; restore strips restricted collections unless the viewer has full scope; restores/resets push immediately and are labelled as such on the server — data-sections.tsx, engine.ts (source: must d, qa-finance#3)
12. Admin seed needs an admin identity — /api/admin/seed requires a workspace admin (ceo/cfo/WORKSPACE_ADMINS) in addition to SEED_TOKEN; UI hidden for non-admins; seeding audited — src/app/api/admin/seed/route.ts, data-sections.tsx (source: must d)
13. Migration 0004 — append-only `workspace_audit` table (UPDATE/DELETE blocked by triggers) + `workspace_snapshot_history` — drizzle/migrations/0004_workspace_audit.sql (source: must e)
14. Server audit row for every workspace write — who (verified email/demo label), source, user id, scope, when, base→new version, bytes, per-collection added/removed/updated counts, protected collections, rejected writes — workspace route + server.ts (source: must e, research-comp#29)
15. GET /api/audit — admin-only, paged (before/limit), filter by actor/action — src/app/api/audit/route.ts (source: must e)
16. Settings › Audit trail (admins) — table with actor, action, version, size, changed collections; filter; CSV export for §13.3 retention — settings/audit-section.tsx (source: must e, live-pass#15)
17. Write-reason labelling — client sends X-Sg-Write-Reason (edit/bootstrap/upgrade/overwrite/restore/reset/merge) recorded in the audit trail (source: qa-finance#3 "log every restore on the server")
18. Mass-deletion guard — non-admin writes that remove >50% of a collection (≥20 rows) or >200 records are rejected (403 bulk_delete_blocked) and audited — server-policy.ts (source: own, qa-finance#3)
19. Server snapshot history + rollback — last 20 versions + one per day for 30 days kept in D1; admins list and roll back to a version from Settings (POST /api/workspace/history) — src/app/api/workspace/history/route.ts, settings (source: own, qa-finance#33)
20. Record-level three-way merge on conflicts — on 409 with local edits, merge per record (by id/userId) against the last server base instead of "server wins + Keep mine overwrites everything"; conflicting records keep the server copy and are counted — src/lib/sync/merge.ts, engine.ts (source: qa-finance#33)
21. PUT input hardening — collection-name whitelist pattern, max 200 collections, records must be objects, JSON depth, clear 400s — server-policy.ts (source: own)
22. CSRF / same-origin guard on all write endpoints (Origin + Sec-Fetch-Site) — src/lib/sync/server.ts (source: own)
23. Content-Security-Policy + COOP/CORP headers in middleware (no eval in production, frame-ancestors none, object-src none) — src/middleware.ts (source: own)
24. /api/health no longer leaks data shape — public callers get liveness only; identified callers get table counts, snapshot info, audit/history table presence and security config — src/app/api/health/route.ts (source: live-pass#1, own)
25. Exponential back-off when the API is down — 30 s → 10 min, reset on success/visibility/manual sync; "next retry" shown — engine.ts (source: must c "stop hammering")
26. Data-scope awareness on the client — sync info carries scope + restricted collections; Settings/sidebar show "your copy excludes other people's pay data (§13.4)" — engine.ts, platform slice, settings (source: must a)
27. Scope-change purge — when the server says scope "own", restricted collections in localStorage are replaced by the redacted server copy even when versions match (a former full copy never lingers) — engine.ts (source: own, qa-finance#2 "every browser keeps a copy in localStorage")
28. Data inventory + size budget — Settings lists every synced collection with record count and KB, warns near D1's ~2 MB row cap; client refuses to push above 1.9 MB with a clear message — settings, engine.ts (source: own)
29. Sync indicator shows last writer and when + locked/own-scope states in the sidebar tooltip — sidebar-extras.tsx (source: live-pass#15)
30. README: Cloudflare Access setup (CF_ACCESS_TEAM_DOMAIN, CF_ACCESS_AUD, WORKSPACE_ADMINS, ALLOW_ANONYMOUS_*), workers_dev/preview_urls risk, personal-data (UU PDP) processing & retention note, audit/history operations — README.md (source: must f, research-comp#43)
